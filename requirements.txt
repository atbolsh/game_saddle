# Hugging Face ecosystem
# Gemma 4 requires a recent transformers (AutoModelForMultimodalLM, gemma4 arch);
# transformers 4.57.1 does NOT have AutoModelForMultimodalLM.
# The model registry's newest architecture (gemma-4-12b, `gemma4_unified`) was
# added in transformers 5.10.0, so that is the repo-wide floor. Models with a
# stricter need declare `min_transformers` in agent.model.MODEL_REGISTRY and
# fail fast with instructions if the installed version is older.
# Verified through 5.14.1 (the cap means "not yet verified past", 2026-07-30):
#   * gliner 0.2.28 declares transformers<5.14, so a FRESH resolve lands on
#     5.13.x with no conflict; manually forcing 5.14.1 alongside it was also
#     verified OK (healthy differentiated GLiNER scores -- its historical
#     transformers-v5 failure mode was uniform ~0.05 scores on every entity).
#   * The Gemma 4 Unified left-pad prefill corruption is present and
#     bit-identical on 5.13.1 and 5.14.1 (scripts/gemma4_pad_batch_repro.py;
#     reported at https://github.com/huggingface/transformers/issues/47651
#     and https://huggingface.co/google/gemma-4-12B-it/discussions/50).
#     The harness works around it (generate_batch dodges the poisoned
#     widths and parity-checks every padded prefill before decoding -- see
#     the banner in agent/model.py); after any transformers bump, rerun
#     the repro script and training/probe_hacky_pads.py.
transformers>=5.10.0,<5.15
